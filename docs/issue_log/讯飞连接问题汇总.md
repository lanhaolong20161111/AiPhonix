## 问题 1: 48195 试题格式错误

### 错误信息

```
48195: 实例评测试卷未设置，试题格式错误。
请检查评测文本是否与试题匹配，
特别是英文题型需要在试题中加特殊标记、未设置ent、category等参数等
```

### 根因

SSB 帧中的 `text` 字段只传了单词文本 `"\uFEFFapple"`，缺少讯飞 ISE 要求的试题格式标记。

**讯飞英文 read_word 题型规范要求：**

```
[word]
apple
```

即 `[word]` 节点 + 换行 + 单词。

### 修复

**文件：** `XfyunSpeechRepository.kt` — `buildSsbFrame()`

```kotlin
// 修改前
private val textWithBom: String
    get() = "\uFEFF$refText"

// 修改后
private val textWithBom: String
    get() = "\uFEFF[word]\n$refText"
```

同时为 SSB 帧新增 `category` 和 `extra_ability` 参数：

```kotlin
// 在 buildSsbFrame() 的 JSON 中添加
"category" to "read_word",           // 英文 read_word 题型
"extra_ability" to "multi_dimension", // 启用多维评测
```

## 问题 2: WebSocket ping 超时

### 错误信息

```
sent ping but didn't receive pong within 15000ms (after 0 successful ping/pongs)
```

### 日志时间线

```
07-34:11.768 D/XfyunSpeech( 4794): 收到评测结果 → XML decoded
07-34:11.768 D/XfyunSpeech( 4794): XML结果(截断): <?xml version="1.0" encoding="UTF-8"?>...
                    ↓ 间隙 28 秒，无任何 XfyunSpeech 日志 ↓
07-34:39.538 E/XfyunSpeech( 4794): WebSocket 错误: SocketTimeoutException (sent ping...)
```

### 根因

`parseXmlToIseResult(resultXml)` 中抛出了未捕获的异常，导致：
1. `webSocket.close(1000, "done")` 从未执行
2. OkHttp WebSocket 连接挂死
3. 15 秒后 ping 超时，连接被强制关闭

### 修复

1. 在 `parseXmlToIseResult()` 外围加 try-catch 包裹
2. `readAttrDouble()` / `readAttrInt()` 安全处理缺失属性

```kotlin
private fun readAttrDouble(parser: XmlPullParser, name: String): Double {
    val value = parser.getAttributeValue(null, name) ?: return 0.0
    return try { value.toDouble() } catch (_: NumberFormatException) { 0.0 }
}

private fun readAttrInt(parser: XmlPullParser, name: String): Int {
    val value = parser.getAttributeValue(null, name) ?: return 0
    return try { value.toInt() } catch (_: NumberFormatException) { 0 }
}
```

## 问题 3: 分数 scale 异常

### 问题描述

`total_score` 返回 `4.585621`，`roundToInt()` 后显示 **5 分**，学生会丧失信心。

### 实际 log 数据

```xml
<read_word accuracy_score="4.585621" total_score="4.585621" ...>
  <syll score="3.984618">
    <phone content="ae" gwpp="-0.606"/>
  </syll>
  <syll score="4.818258">
    <phone content="p" gwpp="-0.044"/>
    <phone content="ax" gwpp="-0.188"/>
    <phone content="l" gwpp="-0.034"/>
  </syll>
</read_word>
```

| 指标 | 原始值 | 0-100 映射 | 含义 |
|------|--------|-----------|------|
| `total_score` | 4.59 | → 5 | ❌ scale 不明 |
| `gwpp` (ae) | -0.606 | → **55** | ✅ /æ/ 难发, 合理 |
| `gwpp` (p) | -0.044 | → **96** | ✅ 爆破音清晰 |
| `gwpp` (ax) | -0.188 | → **83** | ✅ 中等 |
| `gwpp` (l) | -0.034 | → **97** | ✅ 侧音清晰 |

### 结论

- `total_score` 不是 0-100 分，实际 scale 偏低
- `gwpp` 后验概率 log → `100×exp(gwpp)` 映射到 0-100 最合理
- **总分改用所有音素 gwpp 的均值**

### 修复

```kotlin
private fun gwppToScore(gwpp: Double): Int {
    val raw = 100.0 * kotlin.math.exp(gwpp)
    return raw.roundToInt().coerceIn(0, 100)
}
```

`parseResult()` 中总分改为 gwpp 均值。

## 附录二 — 中文拼音评测机制（备用）

### 参数配置

| 参数 | 英文 | 中文 |
|------|------|------|
| `ent` | `en_vip` | `cn_vip` |
| `category` | `read_word` | `read_syllable`(单字) / `read_word`(词语) / `read_sentence`(句子) / `read_chapter`(篇章) |
| `group` | 不支持 | `adult` / `youth` / `pupil` |
| `check_type` | 不支持 | `easy` / `common` / `hard` |

### 中文拼音标注格式

```
[word]           ← 或者 [syllable] 节点
好
hao3
呈
cheng2
```

| 规则 | 说明 |
|------|------|
| 汉字与拼音交替 | 每个汉字一行，下一行是其拼音 |
| `ü` 处理 | `lü→lv`, `nü→nv`, `üe→ue`, 其他用 `u`（如 ju2） |
| 声调取值 | 1-4 = 一二三四声, 0/5/6/7/8/9 = 轻声 |
| 禁止汉字加数字 | 数字只能写在拼音行 |
| 每个字都需标注 | 不能省略 |

### 中英文混合方案

讯飞 ISE **不支持同一连接混合评测**。两种实现思路：

**方案 A — 分两次请求**
```
连接1: ent=en_vip → [word]\napple    → XML 英文结果
连接2: ent=cn_vip → 你好\nni3hao3   → XML 中文结果
```
App 层合并两个结果展示。

**方案 B — 切换到腾讯云 SOE**
腾讯 SOE 的 `EvalMode` 支持 0=英文 / 1=中文，同一接口可分别调用，且有 `ReferencePhone` 字段知道读成了什么音。

## 附录三 — 腾讯云 SOE 评测方案评估（2026-07-21）

### 数据模型对比

| 维度 | 讯飞 ISE（当前） | 腾讯云 SOE（候选） |
|------|----------|-----------|
| **音素评分** | ❌ `gwpp`（后验概率 log 域）→ 手动映射 0-100 | ✅ **每个音素独立 `PronAccuracy` [0-100]** |
| **参考音素反馈** | ❌ 不提供「应该读什么」 | ✅ **`ReferencePhone`** |
| **实际音素** | ❌ 不直接提供「用户读了什么」 | ✅ **`Phone`** — 实际识别结果 |
| **总分** | ❌ `total_score` scale ~4.59, 需猜 | ✅ **`SuggestedScore` [0-100]** |
| **协议** | XML / WebSocket（复杂） | ✅ **纯 JSON / HTTP REST** |
| **中英文同一接口** | ❌ 需两个连接 | ✅ `ServerType=0`(英)/ `1`(中) |
| **单词匹配状态** | 通过 `dp_message` 间接判断 | ✅ **`MatchTag`**: 0=匹配/1=新增/2=缺少/3=错读/4=未录入 |
| **重音检测** | 有限支持 | ✅ `Stress` / `DetectedStress` |
| **评分苛刻指数** | ❌ 无直接等价参数 | ✅ `ScoreCoeff [1.0~4.0]` |
| **文档清晰度** | ✅ XML 格式较清晰 | ⚠️ 官方文档需 JS 渲染，SDK 源码注释是最好文档 |
| **Android SDK** | ✅ 官方 MSC SDK | ✅ Maven 集成 |
| **定价** | 按调用量计费 | 按调用量计费 |

### 推荐配置（英文单词）

```json
{
  "SessionId": "UUID",
  "RefText": "apple",          // 直接传单词，无需 [word] 节点
  "WorkMode": 0,               // 流式分片
  "EvalMode": 0,               // 0=单词模式
  "ServerType": 0,             // 0=英文
  "TextMode": 0,               // 0=普通文本
  "ScoreCoeff": 3.0,           // 适中苛刻程度
  "IsAsync": 0                 // 同步
}
```

### 返回结构示例

```
WordRsp("apple")
  └── PronAccuracy: 85              ← 单词级总分 0-100
  └── PhoneInfos[
       { Phone="æ",  PronAccuracy=85, ReferencePhone="æ",  MatchTag=0 },
       { Phone="p",  PronAccuracy=92, ReferencePhone="p",  MatchTag=0 },
       { Phone="ə",  PronAccuracy=67, ReferencePhone="ə",  MatchTag=0 },
       { Phone="l",  PronAccuracy=90, ReferencePhone="l",  MatchTag=0 },
     ]
```

### 优劣势分析

**优势：**
1. 音素级 `PronAccuracy` [0-100] 直接可用，无需 gwpp 映射
2. `ReferencePhone` + `Phone` 双向反馈，可以做「你读成了 X，应该读 Y」
3. `MatchTag` 四种状态精准匹配
4. 中英文同一接口，便于后续扩展
5. JSON 协议比 XML 简单

**迁移成本：**
1. 需要腾讯云账号 + 开通 SOE 服务 + 获取 SecretId/SecretKey
2. 需要重写 Repository 层（替换 WebSocket/XML 为 HTTP/JSON）
3. Android SDK 集成需要添加 Maven 依赖
4. 现有 UI 层 Model 直接兼容（`PhonemeScore` 字段可复用）
